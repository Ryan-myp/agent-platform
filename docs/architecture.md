# 架构说明

## 目标

支持品牌营销视频、短剧 / 漫剧和长篇作品等创作场景，同时提供无需 brief 的普通聊天。长篇通过独立故事圣经与逐章审阅组织；短剧可选确认分集大纲、链接系列资产，并在本地合成最终视频。左侧“新对话”和“创作流程”是两个独立入口：前者用于自由讨论和按需媒体生成，后者先选择路线，再按阶段生成、审阅并确认脚本、视觉设定、分镜和逐镜任务。创作路线共享项目状态机、Provider 和媒体生产能力，提示词与 Skills 按创作类型隔离。没有可用模型时，工作流项目仍可使用独立手工分镜画布创建、编辑和重排镜头卡片；另有“2D 制作预演”用流程节点和镜头带汇总项目设定、脚本、分镜、逐镜素材、剪辑 / 字幕与交付，读取现有项目状态，不调用模型或自动补齐素材。手工分镜画布在本地持久化并可导出 Markdown，不自动覆盖已确认的工作流分镜。

## 模块

- `app/services/workflow.py`：项目与阶段状态机；草稿可编辑，只有确认当前步骤后才进入下一步。明确标注信息不足或无法继续的草稿不能确认，下游生成会预检已确认内容，并在发现阻塞说明时停止且不调用模型。修改、重新生成和恢复历史版本时保留草稿修订；恢复会归档当前内容并将下游标记为过期。创建时按 `mode=chat|workflow` 区分普通会话和结构化流程，并提供标题重命名及只归档、不删除数据的最近对话移除操作。仅短剧 / 漫剧工作流可绑定未归档系列；生成上下文包含有界系列故事圣经、最多 20 项有效资产和受规则过滤的连续性台账，并将其视为参考资料。前序分集只选编号最近的两集，且只纳入已确认脚本；未确认草稿不作为故事事实传入后续生成。可选分集大纲只有确认后才加入剧本生成上下文。
- `app/services/novels.py`：长篇故事圣经、章节 CRUD、有限修订历史和章节确认；后续生成只参考此前最多两章已确认正文。已确认章节正文修改后会归档旧稿并将后续已有章节标记为待复核，待复核正文不进入后续上下文；文本生成前校验模型配置并记录用量。
- `app/services/series.py`：系列故事圣经、人物 / 场景 / 道具资产与连续性台账的创建、更新、归档和分集读取；台账分集来源必须指向已确认步骤且原文节选逐字匹配，编辑历史有界；归档保留已有记录，剧集编号由存储层事务保证唯一。
- `app/services/chat.py`：会话上下文整理和工具调用循环。普通对话无预设 brief，工作流对话包含项目 brief 和已确认阶段；对话保存在 SQLite，媒体工具在执行前先复述操作并等待明确确认。图片和视频画面作为视觉输入、文档文本作为文本输入；附件按项目归属校验，历史上下文限制为最近 8 个且合计最多 40 MB。
- `app/services/attachments.py`：限制附件类型、数量和大小；在本机提取文本/PDF/DOCX 内容，视频最多分析 6 帧且不含声音。视频帧在进程内做有界 LRU 缓存，避免同一附件在长对话中反复解码；存储清理提供候选预览和二次引用检查。
- `app/stages.py`：`script → prompt → storyboard → scenes → video` 的阶段顺序、公共格式要求和按创作类型区分的提示词要求。
- `config/models.json`、`app/providers/catalog.py`：按 text/image/video/audio 声明模型 ID、厂商适配器、端点、参数、兼容用 API Key 环境变量名和模态默认值；`PUT /api/config/models` 校验、原子持久化并热更新模型目录，公共配置接口不返回 Key。
- `app/providers/credentials.py`：将 API Key 独立保存到数据库同目录的 `model-credentials.json`，使用临时文件原子替换并尽量设置 `0600` 权限；凭据不进入模型目录或项目数据库。
- `app/providers/text.py`：统一文本 Provider 协议、OpenAI-compatible Chat Completions / 工具调用适配器及 Anthropic Claude SDK 适配器。
- `app/providers/media.py`：图像、视频、音频 Provider 和本地媒体资源保存。当前包括 Agnes 图像、拆分提交与查询的 Agnes 视频适配器，以及 OpenAI-compatible 语音/转写适配器。
- `app/skills/loader.py`：扫描本地 `skills/<skill-id>/SKILL.md`，按创作类型与阶段加载 Markdown，并仅内联 frontmatter 显式列出的同目录参考文件；缺少 `tracks` 的旧 Skills 仅按营销路线加载；不执行 Skill 文件代码。
- `app/store.py`：SQLite 项目、独立审阅记录、长篇作品与章节、系列、系列资产、分集索引、聊天消息、附件元数据、逐镜视频任务和用量事件持久化；审阅提交在 SQLite 写事务内核对项目更新时间，避免对刚更新的目标接受陈旧版本意见；分集编号在事务内原子分配并受唯一约束；视频合成通过项目更新时间条件写入，避免覆盖并发修改；附件媒体文件保存到本机媒体目录。聊天记录按 `(project_id, created_at, id)` 建索引并用 keyset 游标分页，避免长对话每次扫描/返回全部消息；项目状态和新视频任务在同一事务写入。后续可替换为 Postgres 实现。
- `app/services/video_jobs.py`：单进程后台 Worker 持久化提交和轮询逐镜视频任务；仅恢复已取得供应商任务 ID 的任务查询，提交不确定时不自动重试。
- `app/services/video_assembly.py`：通过 PATH 或 `imageio-ffmpeg` 查找 FFmpeg，在本地按可编辑顺序合成已确认场景中的就绪本地视频；限制片段数、总输入大小和总时长，检查输出尺寸/时长与源签名，并用条件写入防止并发覆盖。
- `app/services/usage.py`：记录文本与媒体调用状态、耗时、token、可获得的费用和供应商任务 ID；按 UTC 日期汇总媒体调用，并提供默认关闭（0 = 不限）的本地上限。
- `app/services/backup.py`、`app/backup.py`：通过 SQLite online backup 生成一致的数据库快照，归档本地媒体并生成 SHA-256 清单；`verify` 在临时目录校验清单、哈希和 SQLite 完整性，`prune` 默认只预览旧时间戳备份。恢复只写入全新目录；凭据和 `.env` 不进入归档。`GET /api/backup/export` 仅向 loopback 的同源请求提供 ZIP 下载，恢复仍使用 CLI。
- `app/services/reviews.py`：为脚本、分镜、逐镜片段和最终视频计算目标版本指纹；追加审阅记录，校验结论、分类、媒体时间码与陈旧版本，并在内容更新后将旧意见标记为历史记录。
- `app/services/storyboard_canvas.py`：校验并保存最多 24 张手工镜头卡片；通过项目 `updated_at` 条件写入防止并发覆盖，不接触文本、图像或视频 Provider。
- `app/services/project_transfer.py`：为单项目生成/导入校验过的 ZIP 副本；迁移聊天附件、版本绑定的审阅记录、手工分镜画布、系列快照与被引用媒体，为所有记录重映射 ID，排除用量和凭据，并清除供应商任务标识、防止导入后自动续跑。旧项目包缺少审阅文件或手工分镜画布数据时按空历史兼容导入。导入先校验路径、大小、成员清单和 SHA-256，再暂存媒体，最后在 SQLite 事务中插入新记录。
- `app/services/delivery.py`：生成给小团队交接的人读制作 ZIP，包含阶段文稿、逐镜任务、手工分镜 Markdown、Markdown / JSON 审阅历史、状态摘要、README、哈希清单及本地引用媒体；当前有效且大小 / SHA-256 校验通过的最终 MP4 可被收录。包不作为导入/备份格式，不下载远程 URL、不暴露供应商任务 ID 或凭据，且明确说明成片仍需人工审核。
- `app/services/series_transfer.py`：导出/导入整个系列及全部分集、聊天、附件和引用媒体；共享项目包的路径/哈希/体积校验及媒体暂存逻辑，重新映射记录 ID，并在一个 SQLite 事务中插入系列、资产、分集及聊天数据。系列和项目导入都是创建副本，不覆盖现有数据，也不恢复供应商任务。
- `app/services/quality.py`：仅本地确定性启发式检查，覆盖占位与阻塞文本、重复行、内容结构、逐镜任务有效性和时长偏差；结果明确标记为 heuristic-only，不调用模型、不保证创作质量。
- `app/static/`：无构建步骤的工作台 UI，含独立的“新对话”和“创作流程”入口、汇总工作流阶段和镜头顺序的 2D 制作预演画布、可本地编辑/重排/保存和导出 Markdown 的手工分镜画布、长篇故事圣经与章节编辑、分集大纲、镜头资产关联和渲染顺序、最终视频预览、系列连续性台账、项目/系列副本导入与导出、制作交付包下载、草稿历史和恢复、启发式质量检查、服务兼容性提示、用量/视频任务与存储清理对话框、本地备份下载、原生 `<dialog>` 模型配置管理和逐步确认界面。聊天首屏只读最近 10 条，用户可按需向上加载更早记录；分页插入后保留当前阅读位置。聊天发送采用乐观用户消息和 SSE 文本增量更新；助手回复和工作流只读内容安全渲染 Markdown，用户消息保持纯文本。

## 对话和媒体流程

1. 新对话首次发送消息前由前端调用 `POST /api/chat/sessions` 创建 `mode=chat` 会话；它不要求 brief，首条用户消息会成为会话标题。创作流程由 `POST /api/projects` 创建 `mode=workflow` 项目。打开对话时前端调用 `GET /api/projects/{id}/chat/history?limit=10` 读取最近记录；`before` 游标可取前一页，消息按时间正序返回。随后两种模式都通过 `POST /api/projects/{id}/chat/stream` 发送消息：用户消息先在界面显示，服务通过 SSE 返回状态和文本增量；普通聊天使用不含 brief 的上下文，工作流会话使用项目 brief 与已确认阶段内容。兼容的 `GET/POST /api/projects/{id}/chat` 接口仍保留。
2. `POST /api/projects/{id}/chat/attachments` 将附件保存到本机并返回项目绑定的 ID；消息通过 `attachment_ids` 引用，服务验证项目归属。图片/视频视觉输入需所选文本模型支持视觉能力；PDF/DOCX/TXT 等内容先在本机提取文本。每条消息最多 8 个附件、单个 20 MB、合计 40 MB；视频最多分析 6 帧，不解析声音。历史记录每轮最多选取最近 8 个、合计 40 MB 的附件，更早附件会提示重新上传。
3. 文本模型可请求图片、视频、语音生成工具；服务先向用户展示生成内容并等待明确确认，确认前不调用媒体 Provider。工具结果以附件形式保存并显示在对话里。没有 Provider 成功结果时，不得声称媒体已生成。
4. 图像和音频请求当前在聊天 HTTP 请求中同步完成。结构化工作流的逐镜视频任务写入 SQLite 后由单进程后台 Worker 提交和轮询；入队接口返回 HTTP 202，项目状态包含本地任务 ID、供应商任务 ID和状态，前端定时刷新。轮询失败采用有上限的退避重试。服务重启后可按已持久化的供应商任务 ID继续轮询；若进程在提交期间中断或响应无法确认，任务会标为“提交结果待核对”，不会自动重发，必须由用户核对供应商任务后明确确认重试。旧式 Provider 和聊天内媒体工具仍保持同步兼容。
5. Agnes Video 2.5 Flash 单次支持 4–12 秒；平台不会向视频供应商发起跨任务拼接。已确认 `scenes` 且镜头视频就绪并存储在本地时，可调用 `POST /api/projects/{id}/assemble` 使用本机 FFmpeg 合成，最多 24 段、总输入 512 MiB、总时长 30 分钟；结果仍需人工审核。已知 `video_queue_full` 错误会以可操作提示保留供应商请求 ID；平台不会自动重复提交。
6. `scenes` 阶段目前产出逐镜图片提示词，不自动生成场景图片。镜头关联的系列资产只作为文字连续性参考，不会自动上传本地资产文件；改变关联会使已有镜头媒体过期。

## 用量与任务生命周期

`MEDIA_GENERATION_DAILY_LIMIT` 默认 `0`（不限）；非零时按 UTC 日统计本地 SQLite 中的媒体调用。配额检查使用进程内锁，适用于单进程本地 MVP，不保证多进程/多实例并发上限。文本与媒体用量事件保存状态、耗时、可用 token、供应商返回费用和供应商任务 ID；供应商未返回费用时保持未知。

视频任务可取消的范围仅限尚未提交供应商的本地队列项。达到 `VIDEO_JOB_TIMEOUT_SECONDS`（默认 300 秒，最小 60 秒）后，本地停止自动监控并标记超时，不代表供应商任务已取消；恢复操作只续查已有供应商任务 ID。提交结果不确定时必须先核对供应商侧，不能自动重提。未引用附件/媒体清理需先预览并明确确认，删除前会重新检查引用。

## 备份与恢复

工作台的 `GET /api/backup/export` 和 `python -m app.backup create` 都将 SQLite 数据库通过 SQLite backup API 制作快照，再把 `media/` 中的普通文件写入 ZIP。清单记录每个文件的大小和 SHA-256；凭据文件、`.env` 和模型目录不打包。工作台下载接口要求 loopback 客户端及同源浏览器请求；CLI 输出文件已存在时拒绝覆盖。CLI 默认生成带 UTC 时间戳的文件名；`create --keep N` 在新备份成功后轮换旧的时间戳备份，`prune` 默认仅预览，必须添加 `--confirm` 才删除；`verify` 在临时目录解压并检查全部内容。`restore` 在临时目录内校验 ZIP 路径、文件清单、校验和与数据库完整性，成功后原子移动到一个此前不存在的目标目录；不会覆盖线上数据。备份时数据库快照一致，但媒体复制与数据库快照不是跨文件系统事务；若需要统一时间点，先停止服务。

## 项目与系列导入/导出

项目 ZIP 是单项目副本，不是完整数据库备份。它包含项目、聊天消息、聊天附件、关联系列及该系列资产快照，以及记录实际引用的本地媒体；不包含全局用量事件、模型目录和凭据，也不包含原系列的其他分集。导入为全部记录创建新 ID，并将系列作为单分集副本插入；供应商任务 ID 不跨设备迁移，活跃或无法续跑的任务标为中断，导入不会触发 Provider 调用。项目已有关联媒体若不是 `/media/` 下的本地资源，不会被收集为本地文件。

ZIP 导入拒绝重复、不安全、加密或符号链接路径，限制成员数量与解压大小，逐个核对 SHA-256 后才解析数据。媒体先写入同一媒体目录下的临时位置，数据库记录在单个 SQLite 事务中新增；导入失败会清理新媒体，不覆盖旧项目。项目和系列导入端点仅接受 loopback 同源请求，包上限 512 MiB。系列包还要求所有分集均为短剧项目、集数唯一且与源系列关联一致；导入会为系列、资产、分集、消息、附件和审阅记录分配新 ID；旧系列包缺少分集审阅文件时按空历史兼容。导出的非媒体/文档类资源（如 HTML、SVG、PDF、文本和 JSON）由 `/media` 以 `Content-Disposition: attachment` 与 `nosniff` 响应，防止作为同源活动文档内联执行；图片、音频和视频保留内联播放能力。

## 系列故事圣经与连续性台账

系列故事圣经保存题材、世界设定、核心主题、季 / 主线弧光、主要人物弧光、计划结局、叙事基调和内容边界等长期设定。连续性台账条目包含类型、状态、摘要和来源，可手工建立，也可引用某分集中已确认的工作流步骤；分集来源必须通过已确认状态检查，且保存的原文节选必须存在于该步骤内容中。每条记录的修改历史最多保留 12 个版本。

生成上下文只采用 `confirmed` 和 `open` 条目，排除已解决、已归档以及来源分集为当前或未来集数的条目；最多传入 30 条、8,000 字符。已确认条目作为事实，待解决条目作为未解线索提示。前序集数最多选择两集；只有脚本状态为已确认时才带入，单段截取上限为 4,000 字符。用户 brief、系列设定和既有文本都作为参考材料，不作为覆盖系统约束的操作指令。API 契约版本 7 通过 `/api/system/status` 宣告系列、分集大纲、长篇、字幕、本地画幅预设、系列参考图、叙事质量提示、版本绑定审阅和手工分镜画布等功能。

## 分集大纲、长篇与本地合成

分集大纲是可选阶段，只有用户确认的大纲才进入短剧剧本生成参考。长篇以 `novels` 表保存故事圣经和章节；生成只引用较早、已确认的最多两章。修改已确认章节正文会归档其旧版本，并将后续已有章节标为 `stale`；这类章节不会被继续当作事实，需人工复核后重新确认。故事生成调用文本 Provider 前校验模型配置，并记录用量。

镜头可以关联所属系列中的人物、场景和道具资产；关联只传入文字参考，不会把参考图片自动上传到生成供应商。系列资产可在本机工作台附加最多 8 张 PNG / JPEG / WebP 图片，每张最多 20 MiB；文件类型按内容签名校验，存入本地媒体目录，并随系列副本导出。调整镜头资产关联会使已有镜头素材过期，生成队列运行时拒绝修改。

本地视频合成只允许已确认场景和就绪的本地媒体，按剪辑方案确定的顺序组装。项目可保存输出画幅、补边 / 裁切方式和紧凑 / 标准 / 高质量预设；FFmpeg 来源为系统 PATH 或 `imageio-ffmpeg`。最多 24 段、输入总计 512 MiB、总时长 30 分钟，并对输出 MP4 再探测尺寸和时长。已确认镜头任务的旁白、屏幕文字可导出为 SRT / ASS，并可在 MP4 合成时烧录。项目修改、字幕或片段变化会使成片过期；保存依赖项目版本比较，避免合成覆盖并发编辑。功能只在本机运行，不调用媒体 Provider。

## 制作交付包

`GET /api/projects/{id}/delivery` 从制作记录详情下载面向人工交接的 ZIP，要求 loopback 客户端和同源请求。包中分别提供脚本、视觉设定、分镜、逐镜任务（优先保留 JSON）、Markdown 与 JSON 审阅历史、机器可读制作报告、README 与清单；只收集 `/media/` 下可验证的本地引用文件，远程媒体仅记录未下载状态，不写入 URL。当前有效且文件大小及 SHA-256 匹配的最终 MP4 可纳入包；来源签名过期或文件校验失败时会排除并标记状态。该包不是项目导入或数据库恢复格式，不含聊天、用量、模型凭据或供应商任务标识；最终视频仍需人工审核。

## 草稿修订、启发式检查与服务诊断

工作流阶段内容会以有界历史列表保存修订。用户可以把历史文本载入编辑器再保存，或显式恢复为当前稿；恢复前归档当前内容，并将依赖阶段标记为过期。恢复 `scenes` 时重新校验结构并协调逐镜任务，避免镜头 ID 不一致。

`POST /api/projects/{id}/quality/{stage}` 返回本地规则检查结果，包括内容过短、占位/阻塞语言、重复行、逐镜任务格式和总时长偏差；短剧脚本另提供开场钩子、人物目标、阻碍、风险 / 代价和转折等常见词语信号。报告包含评分、严重级别和 `heuristic_only` 标志。叙事信号未检出不代表内容缺失，检出不代表有效；检查不调用 Provider，也不能验证事实、因果、情绪或最终制作质量。

`GET /api/system/status` 提供 API 契约版本、受支持功能、服务实例 ID、启动时间、Python 版本和视频 Worker 状态；页面启动时用它识别旧服务或不完整版本，并展示本机诊断信息及重载页面入口。当前契约版本为 7；新增 `production_reviews` 和 `manual_storyboard_canvas` 功能标记，提供版本绑定审阅与本地手工分镜 API。`GET /api/video-jobs` 汇总本机需关注的视频任务。诊断和同源限制都不提供身份认证。

## 本机请求安全边界

对 `/api/` 下所有非 GET/HEAD/OPTIONS 请求，中间件拒绝不匹配当前 Host/协议的 `Origin`，并拒绝 `Sec-Fetch-Site: cross-site`。未带浏览器来源头的本机 CLI 和自动化请求仍可访问。该机制降低浏览器 CSRF 风险，但不提供身份认证、用户权限、租户隔离或公网安全；服务仍应只绑定 `127.0.0.1`，不能据此暴露到局域网或公网。

## 模式与凭据

普通会话和工作流共享现有项目存储，通过项目 payload 的 `mode` 区分，因此不需要新增 SQLite 表；新对话采用延迟创建，打开空白聊天不会提前写入项目。API Key 可在本机模型配置 UI 填写并显示，单独保存在数据库同目录下的 `model-credentials.json`；保存时尽量设置 `0600` 权限，模型目录/密钥更新与密钥读取 API 仅接受 loopback 请求，读取接口禁用缓存。环境变量仍作为兼容凭据来源。模型目录修改会原子写入 JSON 并立即更新工作流和聊天服务；密钥不会进入模型目录、项目数据库或公共配置接口；已有项目正在使用的文本模型不可删除。应用不包含运行时演示模式；真实模式缺少 Key 时返回配置错误，不回退到伪造结果。自动化测试通过注入隔离的伪 Provider，不会访问线上服务。

## 扩展方向

1. 对接新文本、图像、视频或音频供应商：实现相应 Provider 并在工厂注册，再通过工作台或 `config/models.json` 添加 profile。
2. 生产化媒体任务：将当前单进程 SQLite Worker 替换为支持多实例的队列，补充认证、租户隔离、任务取消、审计、配额/成本控制和跨实例并发保护；当前 `/api/video-jobs` 仅提供本机只读概览，并非多租户任务控制面。
3. 为短剧 / 漫剧路线完善漫剧画风、资产版本和引用关系；将结构化镜头任务逐镜生成图片并支持素材替换。
4. 继续扩展本地剪辑能力，例如可编辑字幕时间轴和 ASS 样式、音轨混音与转场；当前字幕从镜头旁白 / 屏幕文字按镜头时长生成，预设不包含完整专业调色或混音。
5. 生产化前补充身份认证、租户隔离、对象存储、审计、额度与成本控制、上传限制和并发保护。
